# `models.hub` module

## Components

### [`__init__.py`](./__init__.py)

Here, we expose the API of the models.hub runtime. This is used by users to define models or to query information about them.

### [`_hub_make`](./_hub_make)

The code for the command-line dispatcher that users of the model hub interact with.

It is often started via [`hub.make`](../hub.make) at the model hub root, or its symlinks within each model folder.


### [`_infra`](./_infra)

Code for management of the model hub. The code here is not included when someone is using the models. It is only used when contributing or modifying them.


### [`_template`](./_template)

The template used to generate new models. This template code is actually tested to be up to date with the python code.

### [`_dependency`](./_dependency/README.md)

Tests model dependencies across Python environments (training and service). This tool validates that model dependencies can be installed and tested in isolated environments.

### [`hub-config.yaml`](./hub-config.yaml)

Some configs that control how the `infra` behaves. E.g. dev dependencies that we inject for each model, min python version that the wheel of each model expects, etc. In future the dependency constraints for stable vs. experimental models will also go here.


### [`Makefile`](./Makefile)

Command line dispatcher only for the SDK folder

### [`models.yaml`](./models.yaml)

Github actions CI for whole model hub. This is a symlink. The actual file is at [.github/workflows/models.yaml](/.github/workflows/models.yaml) due to GitHub restrictions.

### Tooling configs

The following files are both used to control the behavior of tooling (type checker, pytest, ...) for SDK, and for each model.

The `hub.make` ensures that the same values are generates as boilerplate for each model.

- [`ruff.toml`](./ruff.toml): Config for the ruff checker.
- [`ty.toml`](./ruff.toml): Config for the ty type checker.
- [`ptest.ini`](./ruff.toml): Config for the pytest test runner.

### Test modes

When running tests locally or in CI, you can specify the hardware target:

```bash
#Run cpu only tests
./hub.make test --hardware cpu

# Run GPU tests (gpu_p4dx1)
./hub.make test --hardware gpu_p4dx1

# Run GPU tests on CI
./hub.make test --automation --hardware gpu_p4dx1
```

**CI Behavior:**
- Changed models are automatically detected with their hardware requirements (cpu/gpu_p4dx1)
- CPU tests run on standard runners (`ai-platform-gh-ubuntu-24.04-4core`)
- gpu_p4dx1 tests run on ai-platform-gpu-p4d GPU runners hosted in Ethos with P4d instances
  - CI enforces 8-minute timeout at the GitHub Actions level
- If a model has both CPU and gpu_p4dx1 tests, both will run independently
