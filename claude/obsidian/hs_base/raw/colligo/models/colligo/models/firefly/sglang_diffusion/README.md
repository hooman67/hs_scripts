# `sglang_diffusion` worker

Serves open-source DiT diffusion models via SGLang 0.5.9's `multimodal_gen`
stack. One worker process hosts the full pipeline (text encoder + DiT + VAE)
and exposes a JSON HTTP endpoint.

**Currently supported models** (each auto-registers when its S3 stub is
present):

- `black-forest-labs/FLUX.1-dev` — 12 B image DiT
- `Qwen/Qwen-Image` — 20 B image DiT

**Endpoint shape:** `POST /v1/sglang_diffusion/<owner>/<model-id>`

```json
{
  "prompt": "A photograph of a calico cat at sunset",
  "sampling_params": {
    "num_inference_steps": 28,
    "guidance_scale": 4.0,
    "seed": 42,
    "height": 1024,
    "width": 1024
  }
}
```

Response includes a `presignedUrl` to the generated PNG in temp storage.

## Adding a new model

The model must already be registered in
`sglang.multimodal_gen.registry._MODEL_HF_PATH_TO_NAME`. If not, sglang
upstream needs a `ComposedPipeline` subclass for it first; this worker
can't help.

### 1. Stage weights to S3 (one-time, from a Pluto pod)

```bash
huggingface-cli login --token <YOUR_HF_TOKEN>     # only for gated repos
./models/colligo/models/build/scripts/upload_model.sh "<owner>/<model-id>"
```

The script downloads from HF, uploads to
`s3://colligo-dev-artifacts/artifacts-v1/dit/hf_models/<owner>/<model-id>/`,
and auto-generates the stub at
`models/colligo/models/build/hf_hub/<sanitized>.py` (see
[hf_hub stub](#what-is-an-hf_hub-stub) below). Commit the generated stub.

### 2. Register the worker

Add an enum entry in [`types.py`](types.py) (value = exact HF id) and a
per-worker GPU config in [`build.py`](build.py)'s `_WORKER_CONFIGS`:

```python
# types.py
class SGLangDiffusionWorker(str, Enum):
    My_New_Model = "<owner>/<model-id>"

# build.py
_WORKER_CONFIGS = {
    SGLangDiffusionWorker.My_New_Model: {"tp_size": 1, "memory_gb": 80},
}
```

`available_workers()` picks up the new entry automatically; the app's
`deployments=` list is dynamic, so [`app_sglang_diffusion.py`](../../build/apps/app_sglang_diffusion.py)
needs no edit.

### 3. Lint + commit

```bash
./m lint --paths "models/colligo/models/firefly/sglang_diffusion \
                  models/colligo/models/build/hf_hub/<owner>"
```

### 4. Deploy + smoke test on a Pluto pod

```bash
source m
python -m colligo.rhode.commands.dev_supervisor \
    --spec sglang_diffusion \
    --default-replica 0 \
    --replicas sglang_<canonical_name> 1 \
    --log-to-file
```

`<canonical_name>` is the lowercase, underscore-separated form of the HF id
(e.g. `Qwen/Qwen-Image` → `sglang_qwen_qwen_image`).

Watch for:

1. `Model already exists locally and is complete` — sglang found the staged
   copy; no HF Hub download.
2. `DiffGenerator ready` → `Warmup pass complete`.

Then send a test request via the port-forwarded localhost:

```bash
curl http://localhost:8000/v1/sglang_diffusion/<owner>/<model-id> \
  -H "Content-Type: application/json" -H "Accept: application/json" \
  -d '{"prompt": "test"}'
```

## What is an hf_hub stub?

A Python module under `models/colligo/models/build/hf_hub/` that declares the
S3 file manifest for one HuggingFace repo. Colligo's build system reads it at
deploy time to know what to stage from S3 onto the pod. Each stub exports a
single `MODEL_FILE_SET = build.s3_fileset_source(...)` mapping local relative
paths → S3 pointers (bucket + key + version_id + SHA-256).

Sanitization rule (`_hf_stub_exists` in [`types.py`](types.py)):

```
"Qwen/Qwen-Image"               → colligo.models.build.hf_hub.Qwen.Qwen_Image
"black-forest-labs/FLUX.1-dev"  → colligo.models.build.hf_hub.black_forest_labs.FLUX_1_dev
```

Stubs are auto-generated by `upload_model.sh`; never hand-written.

## Why S3 staging instead of plain HF Hub download

| Concern | Why S3 wins |
|---|---|
| Gated repos need a license-accepted HF token on every pod | License accepted once at upload time |
| HF Hub rate limits / gated-repo throttling | Internal S3 has no such limits |
| Cold-start determinism | Pinned `version_id` + SHA-256 → byte-identical bytes |
| HF Hub availability | S3 is on Adobe's own infra contract |

### How SGLang finds the staged copy

`load_model()` symlinks the staged dir under
`<tempdir>/colligo_sglang_diffusion/<pid>/<short_name>` and passes the
symlink path to `DiffGenerator.from_pretrained`. SGLang 0.5.9's resolver
matches the pipeline class by path basename against registered HF short
names (e.g. `Qwen-Image`), and the colligo-staged dir's basename is a
content hash (`.../file_sets/<sha256>/`) so we can't pass it directly.
Future sglang versions (>= 0.5.12) accept a `model_id` kwarg that makes
the symlink unnecessary; bump together with the env when we move to
Python 3.13 + CUDA 13.
