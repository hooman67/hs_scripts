# V3 Model Hub (models.*)

The **Model Hub** (`models/` in the [[wiki/entities/ai-platform-repo|ai-platform repo]]) — an
opinionated way to **package and share the forward execution of ML models** so the *same* model can
be consumed across inference services, training, and enrichment/data jobs. Each model becomes an
installable package `models.<name>` (e.g. `models.t5_xxl`).

> ⚠️ **Not in active development at ingest** — the `Models` and `Models.DependencyChecks` CI
> workflows are **disabled** (lock files went stale after Artifactory updates). The design below still
> describes the intended shape; reviving it needs the locks refreshed and CI re-enabled.

## The shape of a model

A model folder needs exactly one required Python file:

- **`__init__.py`** — registers the model by exporting a **`models.hub.AIModel`**, and must be
  importable **with no extra dependencies installed** (so the schema can be read without pulling
  heavy runtime deps).
- **`BUILD.yaml`** — dependencies + metadata (e.g. `dev.python_version`).
- **`README.md`** — model docs.
- Recommended: `model.py` for other exported symbols (e.g. the raw `torch.nn.Module`); `_private/*`
  for internals users shouldn't import directly.
- Autogenerated, do-not-edit: `pyproject.toml`, `.python-version`, `py.typed` (managed by `hub.make`
  + CI).

Two install modes (v2.0+): `pip install models.<name>` installs **files/stubs only**; `pip install
models.<name>[model]` also installs the **runtime dependencies**. This mirrors the framework's
"import the API without torch" philosophy.

## The hub SDK (`models/hub/`)

- `hub/__init__.py` exposes the `models.hub` runtime API (define/query models).
- **`hub.make`** — the CLI dispatcher users interact with (symlinked into each model folder); runs
  tests, bumps versions, generates boilerplate, etc. Test hardware is selectable:
  `./hub.make test --hardware {cpu, gpu_p4dx1}`. CI auto-detects changed models + their hardware,
  runs CPU tests on standard runners and `gpu_p4dx1` tests on P4d GPU runners hosted in Ethos
  (8-minute CI timeout).
- `_infra/` (hub management, not shipped with models), `_template/` (tested new-model template),
  `_dependency/` (validates deps install across training **py3.10** and service **py3.12** envs),
  `hub-config.yaml` (injected dev deps, min python).

## How it's consumed

Same model package used across use-cases: enrichment/data jobs (Genie), training infra (Mori
`foundation_exploration`), V2 inference services, and **V3 managed-services** (sample E imports a hub
model into a worker). This shared-consumption goal is the whole point of the hub.
