# Long-Term Plans

## Phase 1 — Dataset discovery

Reconcile the scrape, assess the ticket SKUs, select strong POC candidates, and publish an internal visual
candidate gallery.

## Phase 2 — Generation benchmark

Verify the GPT Image 2.5 contract, define a small prompt matrix, generate traceable variants from clean hero
references, and preserve every prompt, input, parameter, model identifier, seed when available, and output.
Compare against at least one credible alternative model if the initial benchmark exposes a material weakness.

## Phase 3 — Blind C-Tech evaluation

Run a balanced, randomized, identity-hidden real-vs-generated evaluation with per-image realism judgments,
product-identity fidelity ratings, and structured defect tags. Keep evaluation imagery disjoint from prompt
development examples where feasible.

## Phase 4 — Foundry 4.0 POC recommendation

Summarize quality, failure modes, latency/cost, safety/provenance considerations, model/API fit, and the
minimum path from engineering validation to a client-backed pilot using authoritative KDP assets.

## Non-goals

- Treating scraped public imagery as production-approved client data.
- Claiming indistinguishability from a small or unblinded sample.
- Building production infrastructure before the generation and human-evaluation gates pass.
