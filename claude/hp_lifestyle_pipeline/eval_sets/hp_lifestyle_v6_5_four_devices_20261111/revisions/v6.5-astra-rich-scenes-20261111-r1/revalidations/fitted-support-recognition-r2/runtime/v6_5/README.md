# V6.5 source-to-scene writer

Isolated V6.4 successor with actual Astra-authored richer, functional prop
relationships, connected furniture and balanced wall/background composition.
The catalogue retains265 predecessor entries and adds181 environment-specific
choices authored under the user's expansion authorization, for446 entries and
183 distinct repetition groups.

Input remains exactly `smart_brief`, `source_messaging`, `camera_tag`. Both
documents accept structured JSON or text. Output remains exactly ten ranked
candidates with the existing source/C-Tech rubric, exact evidence and inventory.
The GPT-5.5 medium/16000-token writer, one complete-bank repair, camera resolution,
content/device exclusions and main support requirements remain unchanged.

The original global non-repetition remains strict. A narrow same-scene exception
permits a composite display/storage carrier and its separately declared visible
content to share a reserved component family; it does not permit alternative
object duplication, repeated carriers or reuse in another scene. Open displays
require explicit declared contents. Exact new aliases use the existing
longest-phrase recognizer. Astra's per-entry placement/use guidance is supplied
as trusted configuration, never as additional source evidence.

The consultation considered all thirty published C-Tech review comments and
their exact images, including seventeen FAIL and thirteen OK comments. Positive
cases are preserved as regression references. Missing product branding, exact
product illumination/pose and generated geometry remain downstream residuals.
Passing text validation is not human image approval. The PR4523 image pipeline
is not changed.

Run the existing CLI using the approved V6.5 catalogue. `build_assets.py` verifies
the frozen V6.4 predecessor, immutable contracts and exact Astra system patches,
then records the successor asset hashes.
