Set up your review

Add a question and pick its rubric — the set of options reviewers choose from. Each question can use a different one (Yes/No/N‑A, A/B/N‑A, a 1–5 scale, or your own). Every row gets one toggle group per question plus a free-text comment. Questions and answers are saved in this browser; share the report link (with ?q=…) to give others the same questions and rubrics.

Tick hard check to make a question a gate: on any row where it is answered with a red option (No, Fail, a low score — anything the preview colours as the defect), every question below it is greyed out for that row and no longer required. Use it for the question that decides whether the rest is worth asking.

Tick comment to give that question its own comment box — always optional, for the questions where a verdict needs a reason. The row's own comment box stays either way.

Give neighbouring questions the same theme and they are shown under one heading (“Prompt follow · 3 questions”) here and in the Summary tab. It is organisation only: no reordering, and no effect on gating, scoring or publishing.

Publish annotations ×

Your answers live in this browser. Publishing writes them to the report's annotations/ folder on S3 as reviewer_<n>.json — your own numbered slot, reused every time you republish — which the Summary tab reads to tally every reviewer's votes. Your LDAP is inside the file, not in its name. Every loaded row must be fully reviewed first — a row missing an answer to any question that applies to it blocks the publish, and the rows in question are listed below.
